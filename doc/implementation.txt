# Enhancing the GMM-EM Calibration with Cube Constraints

**Overview:** We modify the `jgmm` EM algorithm (a joint GMM-based multi-sensor calibration method) to incorporate additional geometric constraints tailored for a cube-like calibration target. These constraints – planarity of faces, uniform edge lengths, perpendicular faces, and cross-observation consistency – act as **penalty terms** during optimization. By integrating them into the E and M steps of EM, we regularize the solution to preserve the cube’s shape while still fitting the sensor data. This yields a more accurate and stable calibration for structured cube-like datasets, without sacrificing generalizability (the method still works for other shapes, but it especially leverages cube geometry when present).

## 1. Planarity Constraints (Enforcing Planar Faces)

For a cube, all points on a face should lie in a plane. We enforce this by fitting planes to the data for each face and penalizing deviations from planarity:

- **Identify Face Clusters:** Use the current alignment of points (or GMM components) to determine which points belong to which face. For example, cluster points by their surface normal direction or initial face labels (if known). This can be done after each E-step using the current estimated shape.
- **Least-Squares Plane Fitting:** For each face’s cluster of points, perform a least-squares plane fit to find the best-fit plane (compute the plane normal and offset that minimize squared distance to the points). This yields a robust estimate of the face’s orientation and position. (Techniques like SVD/PCA on the points’ coordinates can find the plane’s normal in a stable way.)
- **Penalty Term:** During the M-step, add a penalty for points straying from the fitted plane. For face *f* with normal **n<sub>f</sub>** and distance *d<sub>f</sub>* (from origin), and for each point (or GMM component mean) **x** on that face, include a term: 

  $$C_{\text{plane}}^{(f)} \;=\; \sum_{\text{x on face }f} \big(n_f \cdot x - d_f\big)^2,$$ 

  which is the sum of squared distances of points to the plane. The M-step will then minimize this in addition to the usual GMM likelihood. In practice, this encourages all points for that face to **co-align on a common plane** (maintaining planarity).

- **In EM Integration:** The E-step (responsibility computation) remains unchanged, but after E-step we know which points are grouped to which face (based on current geometry). In the M-step, when updating the model parameters, we modify the update for the **point model (GMM component means)**. Instead of a simple weighted average of points (as in standard GMM), we adjust the points on each face so they lie on the fitted plane. This can be done by **projecting** the tentative updated points onto the plane or by directly solving for plane-constrained means. The plane fitting itself uses the **current** points, and then the means are adjusted toward that plane, effectively incorporating the penalty’s effect. 

- **Stability Considerations:** We weight this penalty with a factor (λ<sub>plane</sub>) to ensure numerical stability. A moderate weight ensures faces become planar without ignoring the actual data. We may start with a small λ and gradually increase it each iteration so that early EM iterations focus on coarse alignment (data likelihood) and later iterations strongly enforce planarity. This avoids oscillations or divergence. Notably, similar approaches are common in calibration – for example, point-to-plane ICP methods leverage planar targets for robust calibration ([GMMCalib: Extrinsic Calibration of LiDAR Sensors using GMM-based Joint Registration](https://arxiv.org/html/2404.03427v1#:~:text=Point,dual%20LiDAR%20system%2C%20utilizing%20planar)).

## 2. Edge Consistency Constraints (Uniform Edge Lengths)

In a perfect cube, all edge lengths are equal. We introduce a constraint to prevent the reconstructed shape from warping (e.g. one side becoming longer than another) when fitting the data:

- **Compute Edge Lengths:** Using the plane parameters from the planarity step, determine the cube’s **corner points** and edges. (For a closed cube, find the intersection of three orthogonal planes to get each of the 8 corner coordinates. Each pair of adjacent corners defines one of the 12 edges.) Compute the length of each edge from these corner coordinates.
- **Penalty Term:** Add a regularization term that penalizes differences in edge lengths. One approach is to enforce all edges to be close to the **mean edge length**. If $L_i$ is the length of edge *i* and $\bar{L}$ is the average edge length across the cube, include: 

  $$C_{\text{edge}} = \sum_{i} \big(L_i - \bar{L}\big)^2,$$ 

  which penalizes the variance in edge lengths. This term is minimal when all $L_i$ are equal. (Alternatively, pairwise differences between every pair of edges or enforcing each edge to match a known target length can be used if the actual cube size is known.)

- **In EM Integration:** During the M-step, after fitting planes and computing corners, we evaluate this edge consistency cost. It influences the update of the **corner positions or the overall scale of the shape**. In practice, we can implement this by adjusting the positions of the planes or corners: for instance, if one edge is shorter than others, the plane positions can be nudged outward to even out the lengths (while still fitting the data). Concretely, if two faces are too close yielding a short edge, we slightly adjust the plane offsets *d<sub>f</sub>* during the M-step update to balance the edge lengths (this is like adding a Lagrange multiplier that enforces equal distances between parallel faces). This adjustment propagates to the GMM component means on those faces (moving them outward or inward to match the new plane positions).

- **Stability Considerations:** Again, use a weight λ<sub>edge</sub> for this penalty. We ensure this term doesn’t dominate the likelihood – it should correct subtle deformations, not drastically move points that deviate due to sensor noise. Starting with a gentle weight and increasing can help the algorithm converge on the correct uniform scale after roughly aligning. By enforcing uniform edges, we maintain the cube’s shape integrity (no unintended stretching/skewing of the model to fit one sensor’s view at the expense of another).

## 3. Face Orthogonality Constraints (Perpendicular Faces)

Cube faces are orthogonal (90° between any two adjacent faces). We enforce perpendicularity of the fitted planes:

- **Calculate Face Normals:** From the plane fitting in step 1, we have a normal vector **n<sub>f</sub>** for each face *f*. We normalize these normals to unit length.
- **Penalty Term:** For each pair of faces that should be perpendicular (e.g. face X and face Y, face Y and face Z, face X and face Z in a cube’s orientation), add a penalty for any deviation from 90°. If **n<sub>i</sub>** and **n<sub>j</sub>** are normals of two different faces, we want **n<sub>i</sub> · n<sub>j</sub> = 0**. We include a term:

  $$C_{\text{ortho}} = \sum_{\text{pairs }(i,j)} \big(n_i \cdot n_j\big)^2,$$ 

  summing over all orthogonal face pairs. This is zero when the normals are exactly perpendicular. (Faces that are opposite each other have parallel normals, which doesn’t enter this sum – we only consider pairs of distinct orientations.)

- **In EM Integration:** We incorporate this in the M-step when updating plane orientations. After obtaining the raw normals from least-squares, we adjust them to satisfy orthogonality **in tandem** with the data fit. One approach is to average the normals to enforce orthogonality: for example, in a cube there are three unique orientation directions (say X, Y, Z axes). We can orthogonalize these directions using a Gram-Schmidt process or singular value decomposition on the matrix of normals. Another simpler method is gradient descent on the above $C_{\text{ortho}}$: rotate each plane’s normal slightly to reduce the dot product with the others while not straying far from the best-fit orientation for the data. Because the points on the faces still need to remain planar, this essentially tweaks the plane orientation minimally. The adjusted normals are then used for the next iteration’s E-step assignment and for refining the plane positions.

- **Stability Considerations:** We apply a weight λ<sub>ortho</sub> and typically keep this constraint **soft**. The normals from data might not be perfectly orthogonal due to noise, so we allow some flexibility. We might enforce this more strongly as the iterations proceed. By the final iterations, the faces will be nearly perpendicular (a hallmark of a true cube). This is analogous to using a known **orthogonal trihedron** as a calibration target and ensuring the algorithm respects its perpendicular geometry ([GMMCalib: Extrinsic Calibration of LiDAR Sensors using GMM-based Joint Registration](https://arxiv.org/html/2404.03427v1#:~:text=Point,dual%20LiDAR%20system%2C%20utilizing%20planar)). It improves accuracy by preventing slight skew in the reconstructed frame.

## 4. Consistency Across Observations (Cross-Sensor Alignment via GMM)

Because multiple sensors observe the same cube, we want a single consistent geometric transformation for each sensor that explains all observations. The GMM-based joint registration inherently provides this by aligning all sensors to one common model ([GMMCalib: Extrinsic Calibration of LiDAR Sensors using GMM-based Joint Registration](https://arxiv.org/html/2404.03427v1#:~:text=multiple%20point%20clouds,based%20point%20cloud%20registration)), and we reinforce it with an optional consistency penalty:

- **Joint GMM Model:** We continue to use a **joint probability model** for all sensor data, as in the original `jgmm`. In the E-step, each sensor’s point observations contribute to the same mixture model of the cube. This means all sensors “agree” on the cube’s shape and pose in the world. The **responsibility** calculation already mixes information across sensors – each point from any sensor is assigned to a common set of Gaussian components (the cube’s features). This **coupling** is what gives consistency: it encourages a transformation for each sensor that aligns its points with the shared cube model, rather than each sensor fitting a separate shape. As a result, the estimated transformations (one per sensor) and the reconstructed cube geometry are consistent with *all* observations simultaneously ([GMMCalib: Extrinsic Calibration of LiDAR Sensors using GMM-based Joint Registration](https://arxiv.org/html/2404.03427v1#:~:text=multiple%20point%20clouds,based%20point%20cloud%20registration)).

- **Penalty Term (if needed):** In cases where we have multiple observation instances (e.g., the cube was scanned at different times or positions), we can add a term to ensure **transform stability**. For example, if the same sensor appears in multiple sessions of calibration, we could penalize the difference in its estimated pose between sessions (encouraging the extrinsic calibration to remain fixed). However, if we formulate the problem such that each sensor has one transform parameter across all observations, this consistency is enforced by design. Thus, an explicit penalty might not be necessary unless the algorithm allowed sensor transforms to vary per observation. Generally, sticking to the joint GMM framework suffices: the shared model acts as a **prior** that ties all sensor data together.

- **In EM Integration:** The E-step remains standard (all points from all sensors are assigned to mixture components based on the current global shape and each sensor’s pose). For the M-step, when updating the sensor transformations, we do a **joint optimization**: all sensors update their rotation/translation to best align with the current global cube model. This can be done by minimizing the weighted alignment error (from the GMM responsibilities) for all sensors at once. Practically, it means each sensor’s transformation is found via a weighted Procrustes alignment of its points to the current mixture means (common model). There’s no separate reference frame per sensor – they all share the model, which imposes consistency. If a consistency penalty is used, it might look like: 

  $$C_{\text{consistency}} = \sum_{\text{sensor }a,\; \text{sensor }b} \|T_a - T_b\|^2,$$ 

  for example, if comparing transforms across time for the same sensor (here $T$ denotes the extrinsic parameters). This would discourage any drift between estimated transformations of the same sensor across multiple observations. In our case of simultaneous calibration, we ensure each sensor has one fixed $T$ across the EM iterations, so this drift penalty is implicitly handled.

- **Stability Considerations:** The joint GMM approach is naturally stable for multiple datasets because it treats **all data uniformly**. To maintain numerical stability with the added geometric penalties, we ensure the GMM likelihood term (which brings in the data from all sensors) is balanced with the constraints. We do not want the constraints to conflict between different sensors’ data – for example, if one sensor’s points are slightly off, the GMM E-step will average it out with others rather than let one dominate. This yields a robust, consistent calibration that leverages all observations. Past studies have noted that such joint registration produces an *unbiased* shape estimate and consistent alignment, as opposed to pairwise or sequential alignments ([GMMCalib: Extrinsic Calibration of LiDAR Sensors using GMM-based Joint Registration](https://arxiv.org/html/2404.03427v1#:~:text=multiple%20point%20clouds,based%20point%20cloud%20registration)). 

## 5. Modified EM Algorithm with Constraints

We integrate the above constraints into the EM procedure by treating them as **additional regularization terms** in the objective function. The standard GMM-EM optimizes the log-likelihood $L$ of the data; we now optimize $L - (\lambda_1 C_{\text{plane}} + \lambda_2 C_{\text{edge}} + \lambda_3 C_{\text{ortho}} + \lambda_4 C_{\text{consistency}})$, i.e. maximize likelihood while **minimizing the penalties**. The algorithm proceeds as follows:

1. **E-Step (Expectation):** Given current parameters (sensor poses and cube model), compute the responsibilities $r_{ij,k}$ that each observation point $x_{ij}$ (point *i* from sensor *j*) belongs to mixture component *k* of the cube model. This is unchanged from the original `jgmm`: we use the Gaussian distances **without** constraints to assign points to components probabilistically. All sensors share the same set of components (the faces/corners of the cube, etc.), which ensures a unified model. The result is a set of weighted correspondences from each sensor’s points to the current global shape.

2. **M-Step (Maximization with Constraints):** **Update the model parameters to maximize the expected log-likelihood minus penalties:**

   - **a. Update Cube Model (Point Positions):** First, ignore constraints and compute the tentative new Gaussian means as the weighted average of all sensors’ points (each point transformed into the common frame by the current sensor pose and weighted by $r_{ij,k}$). This is what a standard GMM-EM would do for the cluster means. **Then apply constraints:**  
     - *Planarity:* For each face, fit a plane to the new points belonging to that face (using their weights). Project the points or adjust the means onto this plane. This can be done by solving a weighted plane fit (ensuring minimal squared orthogonal distance) and then moving each mean to lie exactly on the plane (e.g. set the mean’s coordinate along the plane’s normal equal to the plane’s value at that position). This satisfies the planarity constraint with minimal perturbation to the likelihood fit.  
     - *Edge Length:* Compute corner points from the intersection of the adjusted planes. If any edge lengths differ significantly, slightly reposition the planes or corner coordinates to equalize these lengths. For instance, if one face is too close to its opposite face, move it outward to match the average separation of opposite faces. This effectively scales/translates the means on those faces uniformly to enforce a consistent edge length. Because this is done in a least-squares sense, it won’t violate the point correspondences badly – it finds a compromise between perfectly equal edges and the best fit to data. The penalty term’s gradient can guide how much to adjust each plane’s offset.  
     - *Orthogonality:* Adjust the orientations of the planes (and thus the distribution of means) to make face normals closer to perpendicular. For example, if two normals had a slight acute angle (say 85° instead of 90°), rotate the planes slightly toward 90°. One can rotate the entire set of points on a face around the line of intersection with an adjacent face to correct the angle without losing planarity or moving points off the face. This is a coordinated adjustment – effectively we are optimizing $C_{\text{ortho}}$ by tweaking the normals. The adjustments here and in the previous steps are small if the penalties are small; if large corrections are needed, it indicates the data alignment was quite off, so we iterate again with updated responsibilities to refine.  
     - After these adjustments, we have an updated set of mixture component means (the cube’s key point positions) that balances fitting the sensor data and satisfying the geometric constraints.

   - **b. Update Sensor Transformations:** Now update each sensor’s pose (rotation **R**<sub>j</sub>, translation **t**<sub>j</sub>) to best align its points to the new cube model. This can be done by minimizing the expected squared distance of transformed sensor points to the corresponding GMM means (given by the responsibilities). In practice, this is a weighted Procrustes alignment: for each sensor *j*, form pairs between its points and the current means (with weights $r_{ij,k}$), then solve for the rigid transform that minimizes the error. This is typically solved via SVD on the covariance of point correspondences (ensuring a proper rotation). Because the cube model has been regularized, this step will naturally yield **consistent transforms** – all sensors align to the same shape. (If we had a consistency penalty $C_{\text{consistency}}$, it would enter here: if a sensor had multiple observations, we could couple their transform updates by adding a term that keeps them identical. But in a joint calibration, we usually assign one transform per sensor across all data from that sensor.)
     - *Note:* The transform update is constrained to be rigid (rotation + translation), which inherently preserves lengths and angles of the shape for each sensor’s view. Thus, the sensors cannot introduce any deformation; they can only move and rotate the entire cube. This means that any remaining shape discrepancy must be resolved by the cube model update above – which we have constrained. In other words, the transform update will align each sensor as much as possible to the now nearly-perfect cube, rather than contorting the cube to fit a misalignment. This separation of responsibilities ensures numerical stability and logical consistency (the cube stays a cube; the sensors adjust to it).

3. **Iteration and Convergence:** Repeat the E-step with the new parameters, then the constrained M-step, iteratively. The presence of penalty terms means the classical EM convergence guarantee (which applies to pure likelihood) is not strictly valid, but in practice with small learning-rate-like adjustments and gradually increasing weights, the algorithm converges to a stable solution that balances data fit and constraints. Monitor the change in parameters and the total objective ($L - \sum \lambda C$). Stop when changes are below a threshold.

Throughout this process, each constraint’s weight (λ<sub>1..4</sub>) can be tuned. In early iterations, more emphasis on the GMM term lets sensors roughly align even if the cube is a bit skewed; in later iterations, increasing the weights forces the solution to snap to a cube shape. The final result is a set of sensor transformations that accurately align all sensor data to a **common cube model** and a reconstructed cube shape that is geometrically correct (planar faces, equal edges, orthogonal axes). This leads to improved accuracy on cube-like calibration targets, as the solution leverages known structure in the data (similar strategies have shown robust results in calibration by using planar and orthogonal constraints ([GMMCalib: Extrinsic Calibration of LiDAR Sensors using GMM-based Joint Registration](https://arxiv.org/html/2404.03427v1#:~:text=Point,dual%20LiDAR%20system%2C%20utilizing%20planar)) ([GMMCalib: Extrinsic Calibration of LiDAR Sensors using GMM-based Joint Registration](https://arxiv.org/html/2404.03427v1#:~:text=multiple%20point%20clouds,based%20point%20cloud%20registration))).

## **Conclusion:** 

By integrating geometric **penalty constraints** into the EM updates of the `jgmm` function, we ensure that the multi-sensor calibration preserves the cube’s structure. Planarity, edge consistency, and orthogonality constraints keep the estimated target shape true to a cube, while the GMM joint likelihood ties all sensor observations together consistently. These modifications guide the EM algorithm to a solution that not only maximizes data likelihood but also adheres to physical geometry, yielding a numerically stable and more accurate calibration for structured environments. Importantly, the constraints are implemented as **soft penalties**, so the algorithm remains generalizable – it will default to a standard EM solution if the data do not strongly support a cube shape, but when cube-like structure is present, it capitalizes on it to refine the results. This balanced approach avoids overfitting to noise (thanks to the probabilistic GMM aspect) while preventing geometric distortions, ultimately improving calibration fidelity for cube-based setups.
